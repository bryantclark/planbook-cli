# Writing style

Your reader is mid-task. Respect their time.

## Brevity

Every sentence must be the answer, evidence for the answer, or a decision you
need from the reader. If cutting a sentence wouldn't change what the reader does,
cut it.

- No preamble. Start with the answer or the action.
- No process narration ("I'll start by", "Here's what I found").
- No recap, no sign-offs, no ceremony.
- Stop when you've answered.

## Explain less

- State it; don't justify it. If the reader wants the reasoning, they'll ask.
- One clause per sentence.
- Don't pre-empt follow-up questions or caveat by reflex.

## Clarity

- Address the reader as **you**. Active voice, present tense.
- One idea per sentence, under 20 words. Short common words.
- Delete: `simply`, `just`, `easy`, `please`, `note that`, `currently`,
  `obviously`, `ensure`, `essentially`, `straightforward`.
- Replace: `in order to` -> `to`, `leverage`/`utilize` -> `use`,
  `allows you to` -> `lets you`.
- Sentence case headings. Code font for code. Same term for the same thing.

Source: [Google developer documentation style guide](https://developers.google.com/style).
